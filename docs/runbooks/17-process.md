# 进程 CPU、内存、文件描述符与线程异常

## 覆盖告警指标

`process_cpu_seconds_total`、`process_resident_memory_bytes`、`process_open_fds`、`process_num_threads`

## 现象和触发条件

- 单个进程 CPU 时间、常驻内存、打开文件描述符或线程数量异常增长。

## 影响范围

- 进程可能耗尽节点资源、无法建立新连接、出现句柄泄漏、线程池耗尽或被系统终止。

## 所需证据

- 进程名称/PID、趋势、启动时间、日志、限制值、调用量以及与最近发布的关联。

## 排查步骤

1. 用 `top`、`ps`、`pidstat` 定位 CPU/内存异常进程和增长时段。
2. 文件描述符高时检查 `lsof -p PID`、`/proc/PID/limits` 和连接/文件泄漏来源。
3. 线程高时检查线程 dump、线程池、阻塞调用、队列积压和异常重试。
4. 关联进程日志、应用指标、连接池与上游依赖，确认根因不在外部服务。

## 建议处置

- 修复资源泄漏和异常重试，设置合理的连接、线程和文件描述符上限。
- 临时重启只能作为已经评估业务影响后的缓解措施，随后必须回到根因修复。

## 风险提示

- 不要直接 kill 不明 PID；先确认是否为数据库、容器运行时、系统进程或关键业务进程。

## 恢复验证

- CPU、内存、FD、线程趋势稳定，进程与服务健康检查正常，日志无新增资源耗尽错误。

## 升级条件

- 进程反复崩溃、FD/线程耗尽影响多个服务、或资源问题扩散到节点时，升级处理。

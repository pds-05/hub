# 智能运维监控平台用户使用手册

本文面向平台使用人员，说明如何在网页中完成监控对象接入、告警配置、通知发送、日志查询、Grafana 图表查看和 AI 告警分析。

## 1. 平台能做什么

本平台用于集中管理和查看被监控对象的运行状态，主要能力包括：

- 添加网站、端口、Exporter 类型的监控对象。
- 手动检测监控对象是否可用，并查看检测结果。
- 配置不同等级的告警规则，例如一般、严重、紧急。
- 告警触发或恢复时生成通知记录，并可通过邮箱、Webhook、钉钉、飞书、企业微信发送通知。
- 查询 Loki 中的日志。
- 查看 Grafana 图表。
- 使用 AI 助手针对某个监控对象和某条告警进行交互式分析。
- root 用户可以查看平台自身健康状态。

## 2. 登录与账号

打开平台地址后，进入登录页。

- root 管理员账号：通常是 `admin`。
- 普通用户：可以在登录页注册账号。
- 普通用户只能看到自己的监控对象、告警、通知和 AI 分析。
- root 用户除了普通用户功能外，还可以查看平台健康状态。

建议普通用户不要共用账号，避免监控对象和通知渠道混在一起。

## 3. 首页总览

登录后默认进入“总览”页面。

总览页可以快速看到：

- 当前活跃告警数量。
- 监控对象总数和正常数量。
- 平台节点资源概况。
- 通知记录数量和失败数量。
- 告警等级分布图。
- 监控对象状态图。
- 被监控服务器 Exporter 资源图。
- 最近告警列表。

如果首页出现大量异常，建议优先进入“告警事件”查看具体告警。

## 4. 监控对象

进入“监控对象”页面，可以添加和检测被监控对象。

### 4.1 网站类型

适合监控 HTTP/HTTPS 网站或接口。

示例：

```text
https://www.example.com
https://api.example.com/health
```

可检测内容包括：

- HTTP 状态码。
- 响应时间。
- 是否超时。
- DNS 是否正常。
- HTTPS 证书状态。
- 页面内容是否包含期望关键字。

如果填写“期望关键字”，平台会检查页面内容中是否包含该关键字。

### 4.2 端口类型

适合检测 TCP 端口是否开放。

示例：

```text
114.55.117.211:22
114.55.117.211:6379
114.55.117.211:5432
```

常见端口：

- `22`：SSH
- `80`：HTTP
- `443`：HTTPS
- `3306`：MySQL
- `5432`：PostgreSQL
- `6379`：Redis

### 4.3 Exporter 类型

适合接入 Prometheus `/metrics` 指标地址。

示例：

```text
http://114.55.117.211:9100/metrics
```

常见 Exporter 类型包括：

- node_exporter：Linux 服务器 CPU、内存、磁盘、网络。
- mysql_exporter：MySQL 指标。
- nginx_exporter：Nginx 指标。
- redis_exporter：Redis 指标。
- postgres_exporter：PostgreSQL 指标。
- blackbox_exporter：网站、端口、DNS、TLS 探测。
- 其他自定义 Prometheus Exporter。

注意：Exporter 本身主要提供指标，不直接提供业务日志。

## 5. 告警规则

进入“告警规则”页面，可以配置什么时候产生告警。

### 5.1 告警等级

平台支持三类等级：

- 一般：需要关注，但不一定马上处理。
- 严重：影响明显，需要尽快处理。
- 紧急：可能影响核心服务，需要立即处理。

### 5.2 节点资源规则

适合监控平台支撑节点，例如：

- CPU 使用率。
- 内存使用率。
- 磁盘使用率。
- 系统负载。

### 5.3 监控对象规则

适合监控网站、端口、Exporter，例如：

- 监控对象不可用。
- 响应时间过高。
- HTTP 状态码异常。
- TLS 证书快过期。
- Exporter 不可访问。
- 中间件连接数、内存、请求数等指标异常。

### 5.4 执行告警评估

配置规则后，进入“告警事件”，点击：

```text
执行告警评估
```

平台会根据最新检测数据判断是否触发或恢复告警。

## 6. 告警事件

“告警事件”页面展示已经触发或恢复的告警。

常用操作：

- 详情：查看告警详细信息、处理记录和通知记录。
- 确认：表示已看到这条告警。
- 恢复：手动将告警标记为已恢复。
- Grafana：跳转到相关图表。
- 处理状态：将告警标记为新建、排查中、处置中、观察中、已恢复、已关闭等。

建议处理告警时写处理记录，方便后续 AI 分析知道“人已经做过什么”。

## 7. 通知渠道

进入“通知渠道”页面，可以配置告警通知方式。

支持类型：

- 邮箱
- Webhook
- 钉钉
- 飞书
- 企业微信

### 7.1 邮箱通知

邮箱通知需要填写收件邮箱和发件邮箱 SMTP 信息。

以 QQ 邮箱为例：

```text
收件邮箱：dd_1698@qq.com
SMTP 服务器：smtp.qq.com
SMTP 端口：465
发件账号：你的 QQ 邮箱
SMTP 授权码 / 密码：QQ 邮箱授权码
发件邮箱：你的 QQ 邮箱
SSL 连接：开启
STARTTLS：关闭
```

注意：SMTP 授权码不是网页登录密码，需要在邮箱设置中开启 SMTP 服务后生成。

保存渠道后，可以点击“测试发送”。如果成功，通知记录状态会显示 `sent`。如果失败，错误列会显示原因。

### 7.2 发送规则

通知渠道可以配置：

- 哪些等级发送：一般、严重、紧急。
- 告警触发时是否发送。
- 告警恢复时是否发送。
- 触发通知标题模板。
- 触发通知正文模板。
- 恢复通知标题模板。
- 恢复通知正文模板。

可用模板变量：

```text
$rule_name
$level
$instance
$metric
$value
$operator
$threshold
$message
$trigger_count
```

示例正文：

```text
实例：$instance
指标：$metric
条件：$value $operator $threshold
等级：$level
消息：$message
```

## 8. 通知记录

“通知记录”页面用于查看通知发送结果。

常见状态：

- pending：待发送。
- sent：已发送。
- failed：发送失败。
- skipped：已跳过。

如果通知失败，可以查看错误原因，并在修复配置后重新发送待处理通知。

## 9. 日志查询

“日志查询”页面用于查询 Loki 中的日志。

普通查询模式下可以填写：

- 命名空间。
- 应用或 Pod 关键字。
- 日志级别。
- 关键词。
- 时间范围。
- 返回条数。
- 可选监控对象辅助过滤。

注意：只有已经被 Promtail、Fluent Bit 等日志采集组件采集进 Loki 的日志才能查到。Target 中的 Exporter 地址只提供指标，不代表日志已经接入。

高级模式支持直接输入 LogQL，适合熟悉 Loki 的用户。

## 10. Grafana 图表

“Grafana 图表”页面用于查看 Grafana 中已有的仪表盘。

普通用户可以看到与自己监控对象相关的图表入口。

root 用户还可以看到平台支撑组件相关图表，例如：

- Kubernetes 集群总览。
- 平台节点资源。
- Pod 资源。
- Prometheus。
- Alertmanager。
- Loki。
- Grafana 自身。
- Ingress Nginx。

如果没有匹配到仪表盘，平台会打开 Grafana 搜索或 Explore 页面。

## 11. AI 助手

“AI 助手”用于辅助分析告警。

使用流程：

1. 选择监控对象。
2. 选择该对象下的告警。
3. 点击“开始分析”。
4. 查看 AI 给出的可能原因、验证命令、恢复步骤和风险提示。
5. 继续追问，直到问题排查结束。
6. 点击“退出分析”结束本次会话。

AI 分析会带上：

- 当前监控对象信息。
- 最近检测结果。
- 当前选中的告警。
- 同一对象下的近期告警。
- 告警处理记录。
- 本次会话上下文。

正常监控不会调用大模型，只有用户主动开始分析或继续提问时才会调用。

## 12. 平台健康

只有 root 用户能看到“平台健康”。

这里用于检查平台自身依赖组件是否正常，例如：

- 后端 API。
- PostgreSQL。
- Redis。
- Prometheus。
- Grafana。
- Loki。

普通用户看不到平台健康页面。

## 13. 常见问题

### 13.1 邮件测试失败怎么办

先进入“通知记录”查看错误信息。

常见原因：

- SMTP 授权码错误。
- 邮箱没有开启 SMTP 服务。
- SMTP 端口被服务器安全组或云厂商拦截。
- SSL 和 STARTTLS 配置冲突。
- 收件邮箱格式错误。

QQ 邮箱常见配置是：

```text
smtp.qq.com
465
SSL 开启
STARTTLS 关闭
```

### 13.2 AI 助手没有回复怎么办

检查：

- 是否选择了监控对象。
- 是否选择了告警。
- 后端是否配置了 DeepSeek API Key。
- 后端日志是否有 AI provider request failed。

如果没有配置大模型 API Key，平台会返回本地规则分析结果。

### 13.3 Grafana 打不开怎么办

检查：

- Grafana NodePort 是否正常。
- 浏览器能否访问 Grafana 地址。
- 后端 `GRAFANA_URL` 是否能在集群内部访问 Grafana。
- `GRAFANA_PUBLIC_URL` 是否是浏览器能打开的地址。

### 13.4 日志查不到怎么办

检查：

- Loki 是否正常。
- 日志采集组件是否部署。
- 命名空间、Pod、应用名是否写对。
- 查询时间范围是否太短。

### 13.5 监控对象检测失败怎么办

按类型排查：

网站：检查 URL、DNS、证书、状态码、关键字。

端口：检查 IP、端口、安全组、防火墙、服务是否监听。

Exporter：检查 `/metrics` 是否能访问，返回内容是否是 Prometheus 格式。

## 14. 推荐使用流程

新用户建议按这个顺序使用：

1. 注册或登录账号。
2. 添加监控对象。
3. 手动点击检测，确认对象能正常检测。
4. 创建告警规则。
5. 创建通知渠道，并测试发送。
6. 执行告警评估。
7. 查看告警事件和通知记录。
8. 出现告警时进入 AI 助手分析。
9. 需要图表时进入 Grafana 图表。
10. 需要日志时进入日志查询。

这样使用最稳，也最容易定位问题。

# K8s 智能监控平台十二阶段实施规划

## 阶段 1：准备阿里云 ECS

目标：准备 3 台云服务器。

步骤：

1. 购买 3 台阿里云 ECS。
2. 系统选择 Ubuntu 22.04 或 Ubuntu 24.04。
3. 配置安全组。
4. 开放 SSH、HTTP、HTTPS 和 K3s 节点间通信所需端口。
5. 确认 3 台服务器内网互通。
6. 设置主机名：
   - k8s-control-01
   - k8s-worker-01
   - k8s-worker-02

## 阶段 2：搭建 K3s 集群

目标：让 3 台机器组成一个 Kubernetes 集群。

步骤：

1. 在 control-plane 节点安装 K3s server。
2. 获取 node-token。
3. 在两个 worker 节点安装 K3s agent。
4. 让 worker 加入 control-plane。
5. 使用 `kubectl get nodes` 验证节点状态。

期望结果：

```text
k8s-control-01   Ready   control-plane
k8s-worker-01    Ready   worker
k8s-worker-02    Ready   worker
```

## 阶段 3：安装基础组件

目标：让 K3s 集群具备部署网站的基础能力。

步骤：

1. 安装 Helm。
2. 安装或配置 Ingress Controller。
3. 安装 cert-manager。
4. 配置 StorageClass。
5. 创建命名空间：
   - monitoring
   - platform
   - logging
   - ingress

## 阶段 4：安装 Prometheus / Grafana / Alertmanager

目标：搭建基础监控系统。

步骤：

1. 添加 prometheus-community Helm 仓库。
2. 安装 kube-prometheus-stack。
3. 验证 Prometheus。
4. 验证 Grafana。
5. 验证 Alertmanager。
6. 验证 kube-state-metrics 和 node-exporter。
7. 确认 Prometheus 能采集 K8s 节点和 Pod 指标。

## 阶段 5：安装 Loki 日志系统

目标：让平台具备 Pod 日志查询能力。

步骤：

1. 安装 Loki。
2. 安装 Promtail。
3. 确认 Pod 日志被采集。
4. 在 Grafana 中接入 Loki 数据源。
5. 准备后端调用 Loki API。

第一版日志功能：

- 按 namespace 查询
- 按 pod 查询
- 按关键词查询
- 按时间范围查询

## 阶段 6：设计 FastAPI 后端

目标：开发平台后端 API。

推荐模块：

- auth
- users
- clusters
- metrics
- alerts
- rules
- dashboards
- logs
- assistant
- settings
- audit

后端需要接入：

- Prometheus API
- Alertmanager API
- Grafana API
- Kubernetes API
- Loki API
- 大模型 API
- PostgreSQL
- Redis

第一版优先实现：

1. 登录
2. 集群概览接口
3. 节点指标接口
4. Pod 状态接口
5. 告警列表接口
6. AI 助手接口

## 阶段 7：设计 React 前端

目标：开发网站页面。

推荐技术：

- React
- TypeScript
- Ant Design
- ECharts

主要页面：

1. 登录页
2. 首页总览
3. 监控中心
4. 告警中心
5. 日志中心
6. AI 智能助手
7. 系统管理

## 阶段 8：接入 AI 智能助手

目标：让 AI 能辅助监控排障。

步骤：

1. 配置大模型 API Key。
2. 开发 AI 助手后端接口。
3. 封装 Prometheus、Kubernetes、Alertmanager、Loki 查询工具。
4. 将查询结果整理成结构化上下文。
5. 调用大模型 API。
6. 返回告警解释、原因分析、PromQL 和修复建议。

第一版 AI 场景：

- 解释告警
- 分析 Pod 重启
- 分析 CPU / 内存异常
- 生成 PromQL
- 总结错误日志
- 给出排查步骤

## 阶段 9：部署网站到 K8s

目标：把自己写的网站运行在 K3s 集群里。

步骤：

1. 编写后端 Dockerfile。
2. 编写前端 Dockerfile。
3. 使用 Docker 构建镜像。
4. 推送镜像到 Harbor
5. 编写 Kubernetes Deployment。
6. 编写 Kubernetes Service。
7. 编写 ConfigMap 和 Secret。
8. 将前后端部署到 platform namespace。
9. 验证 Pod 和 Service 状态。

## 阶段 10：配置域名和 HTTPS

目标：用户可以通过域名访问网站。

步骤：

1. 购买或准备域名。
2. 添加 DNS 解析。
3. 将 `monitor.example.com` 指向公网 IP。
4. 配置 Ingress。
5. 使用 cert-manager 申请 HTTPS 证书。
6. 验证 `https://monitor.example.com`。

第一版只建议暴露网站。Prometheus、Alertmanager、Kubernetes API 不直接暴露到公网。

第一版至少完成：

1. 用户可以登录网站。
2. 网站可以展示 K3s 集群指标。
3. 网站可以展示节点和 Pod 状态。
4. 网站可以展示当前告警。
5. 网站可以嵌入或跳转 Grafana Dashboard。
6. AI 助手可以分析一个告警或异常 Pod。

完成这六点，毕业设计主体就成立。
